## 单元测试覆盖

`tests/store.test.js` 用内存存储替身，固定测试时间和编号，验证数据层规则。每个测试独立，不依赖真实浏览器已有的数据。覆盖：

- 初始化示例、新发布状态、完成措辞、重新开启、删除。
- 存储后重新建立实例、图片和昵称持久化、修改昵称不改变归属。
- 无昵称发布、缺失物品、禁止修改示例记录、错误状态。
- 必填空白、字段最大长度、描述最短长度、类型及分类枚举。
- 无效/未来日期、闰年日期、图片类型、超大图片。
- 名称/描述/地点关键词、组合筛选、我的发布隔离。
- HTML 特殊字符作为文本保存（页面防执行另由 Chrome 验证）。
- 写入失败时保留旧记录、损坏存储不覆盖、编号重复不覆盖。
- 草稿恢复、清空、损坏、写入失败。

存储异常测试通过模拟配额不足，检查状态修改报错后原记录是否保持不变。

## Chrome 检查的 20 组流程

1. 直接打开 HTML、显示首屏和示例。
2. 搜索地点、无结果提示和清除筛选。
3. 类型、分类和完成状态组合筛选。
4. 他人示例可查看联系方式，不可管理。
5. 复制权限受限时选中文本供手动复制。
6. 草稿切页与刷新恢复。
7. 不支持的图片提示拒绝。
8. 实际 PNG 图片经压缩，首次发布经过设置昵称后展示详情。
9. 刷新后照片成功加载、文字和昵称仍存在。
10. 状态操作可取消、完成和重新开启。
11. 删除可取消，确认后更新我的发布。
12. 缺失详情只显示空状态，不错误展示其他物品。
13. HTML/脚本样式输入仅显示文本，不产生注入元素。
14. 取消昵称弹窗不会误发布。
15. 未来日期被阻止，列表数据不变。
16. 仅空白的必填字段不能发布。
17. 独立浏览器上下文不共享用户发布或昵称。
18. 小屏首页和发布页无横向溢出。
19. 禁用存储时有提示，不是白屏。
20. 主要测试页面没有未处理脚本异常。

## 如何复现

运行方法见 README 的“开发与测试”。Chrome 测试使用独立上下文，与日常浏览器的数据分开。截图输出到 `artifacts/` 文件夹，包含桌面首页、物品详情及小屏页面；该目录不纳入 Git。

## 测试范围与限制

- 当前没有共享后端，不涉及跨用户联网发布、账号认证或云服务权限测试。
- 小屏布局使用桌面 Chrome 模拟，未做手机实机测试。
- 其他浏览器、插件干扰、全部系统字体及非常旧版本 Chrome 未做完整覆盖。
- 存储配额异常在单元测试中模拟；实际配额取决于浏览器设置与剩余空间。
- 部分直接打开文件的环境会禁止自动复制；页面已提供手动复制回退。
- 移动目录或更换打开地址可能改变存储区域；清除浏览器数据会删除本地记录。
