# 个人 PSP 参考表

项目：拾光校园寻物。范围包括界面设计、微信小程序本地版与云端版，以及网页交付适配。单位：分钟。

以下是耗时分配示例，不是实际工时记录。计划参考合计 12 小时，耗时示例合计 16 小时，其中页面与功能实现安排 10 小时。采用合并阶段的简版 PSP。

| 阶段 | 计划耗时（参考） | 耗时示例 |
| --- | ---: | ---: |
| 计划与任务安排 | 30 | 30 |
| 需求分析与工具学习 | 45 | 60 |
| 界面与数据设计 | 45 | 60 |
| 页面与功能实现 | 420 | 600 |
| 环境联调与测试 | 120 | 150 |
| 说明文档与提交整理 | 60 | 60 |
| 合计 | 720 | 960 |


## 工作内容

- 需求与设计：参考已有原型，围绕发布、搜索、查看详情、联系发布者和更新状态组织页面，删除帮助、关于等冗余入口。
- 小程序实现：完成寻物与招领、本地缓存、我的发布、状态更新和草稿保存，区分新发布与已完成状态。
- 云端接入：增加共享数据库、云存储图片、微信身份识别和发布者权限校验；昵称只用于展示，不替代微信身份。
- 反馈修复：根据真机反馈，修复详情加载时误显示“信息不存在”和跨账号图片访问问题；将登录入口调整为设置昵称。
- 测试：本地小程序 9 项、云端小程序 70 项自动测试；网页另有 32 项单元测试和 20 组 Chrome 流程检查。
- 交付适配：增加可直接打开 HTML 的 Chrome WEB 版本，整理运行说明、目录结构、测试记录和个人 PSP。

## 复盘

- 安排重点：为页面实现、数据接口、表单校验和状态管理分配较多时间；云端环境、图片访问和权限检查单独安排联调与测试。
- 改进方向：先验证发布到状态更新的完整流程，再调整界面；后续分别记录实现、测试和等待时间，减少事后拆分的误差。
